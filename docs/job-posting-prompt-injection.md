# 채용공고 항목의 프롬프트 주입 흐름

## 개요

채용공고에서 추출한 항목들이 면접 에이전트의 시스템 프롬프트에 어떻게 주입되는지를 설명합니다.

---

## 1단계: 채용공고 파싱

**파일:** `app/api/job-posting/analyze/route.ts`

URL 또는 직접 붙여넣기로 받은 텍스트를 LLM에 넘겨 8개 항목을 JSON으로 추출한 뒤 Supabase `job_postings` 테이블에 저장합니다.

| LLM 추출 키 | DB 컬럼 |
|---|---|
| 업무 내용 | `responsibilities` |
| 지원 자격 | `requirements` |
| 우대 사항 | `preferredQuals` |
| 회사명 | `companyName` |
| 사업부 | `divisionName` |
| 기술스택 | `techStack` |
| 회사 소개 | `companyDescription` |
| 조직 문화 | `companyCulture` |

회사명이 있으면 DART/홈페이지 수집(`collectCompanyInfo`, `collectHomepageInfo`)을 백그라운드로 실행합니다.

---

## 2단계: 외부 데이터 보강

**파일:** `lib/interview-context.ts` → `loadJobPostingWithContext()`

면접 세션 시작 시 `job_postings` 외에 `company_info` 테이블에서 추가 항목을 합쳐 `JobPostingContext` 객체를 구성합니다.

| 출처 | 항목 | 조건 |
|---|---|---|
| DART | `foundedYear`, `listingStatus`, `financialSummary`, `employeeSummary`, `businessSummary` | 항상 |
| 홈페이지 | `industrySector`, `mainServices`, `visionMission`, `coreProduct`, `targetCustomer`, `competitivePosition` | 항상 |
| 네이버 뉴스 | `newsContext` | `normal` / `hard` 난이도 + 직무 분류 감지 시. 24시간 TTL 캐시 |
| 직무 분류 | `jobClassification` | 난이도 옵션이 있을 때 (`detectJobClassification()` 로 21개 중 분류) |

---

## 3단계: 에이전트별 선별 주입

**파일:** `lib/interview.ts` → `buildAgentSystemPrompt()`

3명의 면접관은 역할에 맞게 서로 다른 항목을 받습니다.

| 항목 | 면접관1 (HR) | 면접관2 (팀장) | 면접관3 (선임) |
|---|:---:|:---:|:---:|
| 담당 업무 / 자격 요건 / 우대 사항 | ✅ | ✅ | ✅ |
| 회사명 / 지원 사업부 | ✅ | ✅ | ✅ |
| 업종 | ✅ | ✅ | ✅ |
| 최근 뉴스 | ✅ | ✅ | ✅ |
| 기술스택 | ❌ | ❌ | ✅ |
| 주요 서비스 / 핵심 제품 | ❌ | ❌ | ✅ |
| 직무 분류 | ❌ | ✅ | ✅ |
| 설립연도 / 상장 현황 / 직원 현황 | ✅ | ❌ | ❌ |
| 재무 요약 / 사업 요약 | 힌트로만 추상화 | ❌ | ❌ |
| 비전/미션 / 타겟 고객 / 경쟁 포지셔닝 | ✅ | ❌ | ❌ |
| 회사 소개 / 조직 문화 | ✅ | ❌ | ❌ |

---

## 4단계: 원시 데이터 → 해석된 힌트로 변환

일부 항목은 LLM에 직접 넘기지 않고, 코드에서 먼저 분류해 **질문 방향 지시문으로 변환**합니다.

### 재무 국면 (`financialSummary`)

`classifyFinancialPhase()` → 아래 3가지 중 하나로 분류 후 힌트 주입 (원본 수치 미노출)

| 분류 | 조건 | 면접관 힌트 방향 |
|---|---|---|
| 확장기 | 매출 성장 ≥ 20% (영업 적자여도) | 변화·확장 환경 적응 가능 여부 파악 |
| 위기 | 매출 감소 + 영업 흑자 | "왜 이 시점에 이 회사인가" 진정성 검증 |
| 생존모드 | 영업 적자 | 단기 성과 압박 환경 각오 확인 |

### 기업 성숙도 (`foundedYear` + `listingStatus` + `employeeSummary`)

`classifyCompanyMaturity()` → 양 극단만 분류 (셋 중 하나라도 결측이면 미주입)

| 분류 | 조건 | 면접관 힌트 방향 |
|---|---|---|
| 초기 | 설립 ≤ 8년 + 비상장 + 임직원 ≤ 300명 | 자기주도성, 유연성, 리소스 부족 성과 경험 파악 |
| 성숙기 | 설립 ≥ 15년 + 상장 + 임직원 ≥ 2,000명 | 대규모 조직 협업, 절차 기반 실행, 전문성 깊이 파악 |

### 고객 유형 (`targetCustomer`)

`detectCustomerType()` → B2B / B2C / UNKNOWN 분류 후 면접관1, 면접관3에 별도 힌트 주입

- **면접관1 (HR):** B2B/B2C에 따라 서비스 이해 검증 방식 분기, 고객층 매핑 힌트 추가
- **면접관3 (선임):** B2B면 안정성·권한 관리 경험 우선, B2C면 트래픽·최적화 경험 우선

### 비전/미션·차별점 유효성 검증

| 항목 | 함수 | 기준 |
|---|---|---|
| `visionMission` | `isValidVisionMission()` | 구체 키워드 포함 + 추상 문구만 있지 않을 것 |
| `competitivePosition` | `isValidDifferentiation()` | 마케팅 문구가 아닌 실질 차별점 포함 |

유효한 경우에만 "앵커 질문" 가이드 형태로 주입합니다.

## 평가 단계의 프롬프트 주입

**파일:** `lib/agents.ts` → `buildContextBlock()`

면접이 끝난 뒤 BARS 채점·토론·중재 단계에서도 `JobPostingContext`가 주입됩니다. 다만 면접 단계와 목적이 달라 주입 항목이 다릅니다.

### 면접 vs 평가 비교

| 항목 | 면접 (질문 생성) | 평가 (채점/토론) | 비고 |
|---|:---:|:---:|---|
| 담당 업무 / 자격 요건 / 우대 사항 | ✅ | ✅ | |
| 회사명 / 지원 사업부 | ✅ | ✅ | |
| 설립연도 / 상장 현황 / 직원 현황 | ✅ (면접관1) | ✅ (면접관1) | DART |
| 회사 소개 / 조직 문화 | ✅ (면접관1) | ✅ (면접관1) | 채용공고 추출 |
| 사업 요약 | 힌트로 추상화 | ✅ (면접관1) | DART |
| 비전/미션 | ✅ (면접관1) | ✅ (면접관1) | 홈페이지 |
| 업종 | ✅ (면접관1·2·3) | ✅ (면접관2) | 홈페이지 |
| 기술스택 | ✅ (면접관3) | ✅ (면접관3) | 채용공고 추출 |
| 직무 분류 | ✅ (면접관2·3) | ✅ (면접관2·3) | |
| 주요 서비스 | ✅ (면접관3) | ✅ (면접관3) | 홈페이지 |
| 재무 요약 | 힌트로 추상화 | ❌ | DART — BARS 채점 기준 없음 |
| 타겟 고객 / 경쟁 포지셔닝 | ✅ (면접관1) | ❌ | 질문 전략용 |
| 핵심 제품 | ✅ (면접관3) | ❌ | 질문 전략용 |
| 최근 뉴스 | ✅ | ❌ | 질문 전략용 |
| 재무국면·기업성숙도·B2B/B2C 힌트 | ✅ | ❌ | 전략 힌트 — 채점 불필요 |

### 평가에서 제외하는 기준

평가의 원칙은 **"답변에 명시적으로 드러난 내용만 채점"**입니다. 이 원칙에서 두 가지 기준이 나옵니다.

1. **포함:** BARS 채점 기준이 참조하는 사실 정보 — 평가자가 지원자 답변의 정확성·구체성을 판단하려면 실제 회사 정보가 필요합니다. (`직무·회사 이해도` 기준에서 "구체적 조사 근거 드러남"을 채점하려면 실제 비전·사업 요약·직원 현황을 알아야 함)

2. **제외:** 질문 방향 힌트용 데이터 — 평가에서 이런 데이터가 있으면 답변에 없는 내용을 좋게 추론하는 노이즈가 됩니다.
   - `financialSummary`: BARS 어디에도 재무 수치 지식을 채점하는 기준 없음
   - `targetCustomer` / `competitivePosition` / `coreProduct`: B2B/B2C 분기·차별점 인지는 질문 전략이지 채점 기준이 아님
   - `newsContext`: 뉴스 활용은 질문 생성 전략 — 지원자가 언급하지 않은 뉴스를 평가자가 알면 편향 발생

### 평가 단계 프롬프트 구조 (`buildContextBlock()` + `AGENT_SYSTEM_PROMPTS`)

```
시스템 프롬프트:
  [에이전트 평가 철학]
  [BARS 채점 원칙] — 답변 직접 인용, 추론 시 "(추론)" 표시
  [BARS 앵커] — 에이전트별 0~100 구간 행동 묘사

유저 프롬프트:
  [지원자 배경] — buildProfileSummary() 결과
  [채용 직무]   — 에이전트별 선별된 채용공고 + 외부 데이터 (사실 정보만)
  [면접 대화 기록] — 전체 Q&A
```

Round 0(독립 채점) → Round 1(스탠스 피드백) → Round 2a(재반박) → Round 2b(스탠스 갱신) → 중재자 종합 모두 동일한 `buildContextBlock()` 결과를 재사용합니다.

## 최종 시스템 프롬프트 구조 (`buildAgentSystemPrompt()`)

```
[에이전트 페르소나 + 판단 철학]
  └─ (면접관1만) DART 힌트 (재무 국면, 기업 성숙도, 사업 요약 활용 지침)
  └─ (면접관1만) 홈페이지 힌트 (비전 앵커, 서비스 이해, 고객층 매핑, 차별점 인지)
  └─ (면접관3만) B2B/B2C 기술 평가 방향 힌트

[면접 난이도]
  └─ tutorial / easy / normal / hard 별 질문 톤 가이드

[채용공고]
  └─ 에이전트별로 선별된 항목 텍스트 블록

[최근 업계 뉴스 및 동향]  ← newsContext가 있을 때만
  └─ 뉴스 활용 지침
  └─ 직무별 뉴스 주제 질문 가이드

[지원자 프로필]
  └─ buildProfileSummary() 결과

[면접 가이드]
  └─ buildContextualHints() — 경력/신입 분기, 전공-직무 불일치 감지
```
